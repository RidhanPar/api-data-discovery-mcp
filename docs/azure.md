# Azure deployment

```
make azure-test    # offline: terraform fmt + validate + plan tests with mocked providers
make azure-cost    # monthly estimate from live Azure list prices
make azure-up      # deploy (az login + infra/terraform.tfvars)
make azure-down    # destroy everything
```

## What gets deployed

```
                Internet
   MCP clients ───────────────┐            approvers / admins (admin_cidrs only)
                              ▼                          │
 ┌─ Container Apps environment (VNet 10.40.0.0/23, Consumption) ────────────────────┐
 │  mcp (external) ──► catalog (internal) ◄── n8n (external, IP-restricted, min 1) │
 │        ▲                │      ▲                 │          │                   │
 │        │                │      └── agent (internal)◄────────┘                   │
 │  keycloak (external)    │            │                      └──► mailpit (TCP, internal)
 │  ingest job (manual)    │            │                                          │
 └─────────────────────────┼────────────┼──────────────────────────────────────────┘
          private subnet   ▼            ▼  managed identity, keys disabled
        PostgreSQL Flexible B1ms     Azure OpenAI (chat + embeddings)
        nordlys | n8n | keycloak     
   Key Vault (RBAC, per-secret grants) · ACR Basic · Azure Files (registrations) · Log Analytics · budget
```

| Concern | Choice | Why |
|---|---|---|
| Compute | Container Apps, Consumption profile | Scale to zero; the same images as docker-compose; the app names (`catalog`, `n8n`, ...) are the internal host names, so service URLs match compose |
| Always on | n8n and Mailpit only (`min_replicas = 1`) | n8n Wait nodes (approval timeouts) need a running process; Mailpit keeps mail in memory. Everything else scales to zero |
| Database | PostgreSQL Flexible Server B1ms, PG 17, pgvector allow-listed | Cheapest tier with pgvector; private subnet + private DNS, no public endpoint |
| Secrets | Key Vault, RBAC mode | Every secret is generated by Terraform and stored only in Key Vault (and the Terraform state, see below). Container Apps reference secrets by Key Vault URL, so a rotation in Key Vault reaches the apps on the next revision |
| Identity | One user-assigned managed identity per app | Each identity is granted `Key Vault Secrets User` on **individual secrets**, `AcrPull`, and `Cognitive Services OpenAI User` only where needed. The MCP server cannot read database credentials; only n8n can read the link-signing secret (asserted in `infra/tests/plan.tftest.hcl`) |
| LLM + embeddings | Azure OpenAI, `local_auth_enabled = false` | No API keys exist; the apps authenticate with their managed identity (`DefaultAzureCredential` + `AZURE_CLIENT_ID`). Anthropic/OpenAI remain available through the same provider interface by setting `NORDLYS_LLM_PROVIDER` |
| Networking | n8n restricted to `admin_cidrs` + the app subnet | The n8n editor and the approval links are for staff on the corporate network/VPN. MCP and Keycloak's token endpoint are public, protected by OAuth |
| Logs | Log Analytics, 30 days, 1 GB/day cap | The cap is a cost guard; JSON logs from every app land here |
| Cost guard | Budget on the resource group: 50/80/100% actual, 100% forecast | E-mails `budget_emails` |
| Teardown | Everything in one resource group; Key Vault and Azure OpenAI purged on destroy | `make azure-down` leaves nothing billable and allows an immediate redeploy |

**Embeddings in Azure.** `embedding_provider = "azure-openai"` (default) uses
`text-embedding-3-small` truncated to 384 dimensions, so no schema change is needed. The
retrieval numbers in the README were measured with the local ONNX model; with Azure
embeddings they must be re-measured (`make eval-retrieval` with
`NORDLYS_EMBEDDING_PROVIDER=azure-openai`) and are reported separately. Set
`embedding_provider = "onnx-local"` to run the measured configuration in Azure.

**Terraform state contains the generated secrets.** Fine for a personal demo with local
state; for anything shared, use the commented `azurerm` backend in `infra/versions.tf`
(encrypted storage, Entra ID auth, no shared keys).

**Lock file.** `infra/.terraform.lock.hcl` is not committed: the build environment could
only install Linux provider packages from a filesystem mirror, which would pin hashes
for Linux only. Run `terraform init` once and commit the lock file it creates.

## Identity: Entra ID instead of Keycloak

Keycloak is deployed as a container so the Azure environment runs exactly the code and
realm that were tested locally. In a real Azure tenant, Entra ID replaces it. The
services already validate standard OIDC JWTs (issuer, audience, signature from JWKS), so
the change is configuration plus claim mapping, not a rewrite.

| Keycloak (today) | Entra ID |
|---|---|
| Realm `nordlys`, issuer `https://keycloak.../realms/nordlys` | Tenant; issuer `https://login.microsoftonline.com/<tenant>/v2.0` |
| Clients `nordlys-mcp`, `nordlys-catalog`, `nordlys-agent` audiences | One app registration per API, `Application ID URI` = audience (`api://nordlys-mcp`) |
| Client scopes `catalog.read`, `dataproduct.read`, `access.request` | Delegated permissions (`scp` claim) exposed by the MCP app registration |
| Service clients (`nordlys-mcp-server`, `nordlys-n8n`) with client secrets | Managed identities with **app roles** (`roles` claim), so no secrets at all |
| Realm roles for data-product grants (`dp:claims-fraud-scores`) in a `roles` claim | App roles on the catalog app registration, assigned to users or groups |
| Workflow A grants a realm role via the Keycloak admin API | Workflow A creates an `appRoleAssignment` via Microsoft Graph (`POST /servicePrincipals/{id}/appRoleAssignedTo`), using n8n's managed identity with `AppRoleAssignment.ReadWrite.All` |
| On-behalf-of headers from trusted services | The OAuth 2.0 on-behalf-of flow: the MCP server exchanges the user's token for a catalog token, so the user identity is signed by Entra ID |

Code changes needed: read scopes from `scp` (space-separated) as well as `scope`, and
accept `roles` for app permissions. `security/jwt.py` is the only place that maps
claims to a `Principal`, so this is contained. Conditional Access, MFA and group-based
assignment then come from Entra ID for free.

## Azure API Management: where it would sit, and why it is not deployed

APIM belongs in front of the **public** surface: the MCP endpoint, and the catalog API if
other teams call it directly. It would take over rate limiting (one shared limit across
replicas instead of the in-process token bucket, see `security/ratelimit.py`), JWT
validation at the edge (`validate-jwt`), request-size limits, and per-consumer
subscriptions and analytics.

It is not deployed because the catalog is deliberately **internal** (VNet-only ingress),
and the cheapest tier, Consumption, cannot reach VNet-internal back ends. The tiers that
can (Developer without SLA, Premium, or Standard v2 with VNet integration) cost more
than this environment's whole monthly budget. The trade-off is documented rather than
hidden: in-process rate limits are per replica, so with N replicas the effective limit is
N times the configured one.

## What was verified, and what was not

| | Status |
|---|---|
| `terraform fmt`, `terraform validate` against azurerm 4.81.0 | Passes |
| Offline plan tests with mocked providers (`terraform test`): private DB, no OpenAI keys, per-secret grants, IP restriction on n8n, scale-to-zero, budget alerts | 2 runs, all assertions pass |
| Keycloak realm placeholders (`${MCP_CLIENT_SECRET:...}`) are resolved from the environment at import | Verified against Keycloak 26.4 locally |
| Azure OpenAI managed-identity code path (`azure_ad_token_provider`) | Unit-level only: no Azure access from the build environment |
| `make azure-up` against a real subscription | **Not run yet**: the build environment cannot reach `management.azure.com`. Expect to fix small things on the first apply (model availability in the region, quota) |
| `make azure-cost` | **Not run yet**: the Retail Prices API is blocked from the build environment. The script prints every meter it uses, so its output can be checked |

Known risks on the first apply: model versions/quotas for `gpt-4.1-mini` and
`text-embedding-3-small` in the chosen region (variables `chat_model`,
`embedding_model`); Mailpit's TCP ingress host name (`mailpit:1025`) for n8n's SMTP
credential.
